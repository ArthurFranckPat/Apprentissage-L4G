Les transactions

Écrire en base, c'est « tout ou rien ». Voici l'interrupteur.

Tu connais les transactions (ACID). En L4G, trois mots les pilotent, et il y a une règle X3 qui surprend les débutants. On voit les deux.

Les trois mots

Trbegin [YYNV2]                              # j'ouvre : tout ce qui suit est en attente
Update [YYNV2] Where [YYNV2]NAVETTE=[L]NAVETTE With [YYNV2]VALFLG=2
Commit                                       # je valide : tout est écrit d'un coup
  • Trbegin [TABLE] — démarre, et verrouille la/les tables listées.
  • Commit — persiste tout et libère les verrous.
  • Rollback — annule tout depuis le Trbegin, libère aussi.
Valider une navette = passer VALFLG à 2 (validée). C'est exactement ce bloc de YNAVETTE. La transaction garantit qu'on ne se retrouve jamais avec une navette à moitié validée : soit le statut bascule entièrement, soit rien.

La règle qui surprend : un seul niveau

Le moteur X3 ne gère qu'une transaction à la fois. Pas d'imbrication. Si ton subprog fait Trbegin alors qu'une transaction tourne déjà (lancée par l'appelant), c'est l'erreur.

D'où l'idiome If adxlog. La variable système [S]adxlog vaut non-zéro si une transaction est déjà en cours :

Local Integer IF_TRANS
If adxlog
    Trbegin [MATABLE]      # personne n'avait ouvert -> j'ouvre, je suis le patron
    IF_TRANS = 0
Else
    IF_TRANS = 1           # l'appelant a déjà ouvert -> je ne touche pas
Endif

# ... écritures ...

If IF_TRANS = 0 : Commit : Endif   # je ne commit QUE si c'est moi qui ai ouvert

Idée : un subprog réutilisable ne doit pas casser la transaction de celui qui l'appelle. Il n'ouvre/ferme que s'il est le propriétaire.

Jamais de temps long dans une transaction. Pas de question utilisateur (OUINON), pas de gros calcul, pas d'appel distant entre Trbegin et Commit : les verrous tiennent tout ce temps → blocages et deadlocks. C'est pour ça que YNAVETTE pose la question avant ($EXEBOUT), puis ne transactionne qu'à la toute fin de VALIDE_NAVETTE.

Le squelette sûr d'une écriture

Trbegin [T]
Readlock [T]KEY0 = [L]K        # lit ET verrouille la ligne
If fstat : Rollback : End : Endif   # (leçon 3 : on teste toujours)
[F:T]CHAMP = nouvelle_valeur
Rewrite [T]
If fstat : Rollback : End : Endif
Commit

Chaque chemin d'échec fait Rollback : on ne laisse jamais une transaction ouverte ni un verrou pendant. Op → test → rollback si KO.
