Leçon 3 · Base de données · ~6 min

fstat, le garde-fou

Le code retour que personne n'affiche, mais que tout le monde doit tester.

L4G n'a pas d'exceptions. Une lecture qui échoue ne « lève » rien : elle pose discrètement un code dans la variable système [S]fstat et continue. Si tu ne le testes pas, ton code avance avec des données fausses — et personne ne le sait.

Read [YNV]NAVETTE = PNAV
If fstat                       # fstat ≠ 0  ->  échec
    Errbox "Navette introuvable"
    End
Endif
# ici, et seulement ici, [F:YNV] est fiable
La règle d'or : fstat = 0 = succès. Toute autre valeur = problème (non trouvé, verrou, erreur). Après chaque Read, Write, Rewrite, Delete, For, Openo, Wrseq → tu testes fstat. Sans exception.

Les deux écritures qui veulent dire la même chose

En L4G, un entier non nul est « vrai ». Donc ces deux formes sont équivalentes :

If fstat        # vrai si fstat ≠ 0  -> ÉCHEC
If fstat = 0    # vrai si succès

YNAVETTE utilise la forme explicite, plus lisible, partout :

Read [F:YSOH2]SOH0 = [M:YNV1]SOHNUM(I)
If [S]fstat = 0
    [M:YNV1]BPCORD(I) = [F:YSOH2]BPCORD   # n'agit que si la lecture a réussi
Endif

Ici, le nom du client n'est recopié que si la commande a bien été trouvée. Sans ce test, une commande absente écraserait BPCORD(I) avec les restes de la lecture précédente.

Teste fstat tout de suite. Beaucoup d'instructions le réécrasent. Si tu intercales du code entre l'op et le test, tu lis peut-être le fstat d'autre chose. Op → test, collés.

Lire le bon « identifiant » : l'index, pas le champ

Détail qui piège : Read se fait par nom d'index, pas par nom de champ. Dans Read [YNV]NAVETTE = PNAV, NAVETTE est ici le nom de la clé. Et Read [F:YSOH2]SOH0 = … : SOH0 est l'index primaire de SORDER (souvent <ABV>0). Mauvais index → échec silencieux (donc… on teste fstat).
