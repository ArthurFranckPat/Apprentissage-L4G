L'écran et la base

[M:] vs [F:] — les deux mondes que tout objet relie.

Un objet X3 vit entre deux buffers mémoire distincts. Tout le travail consiste à faire transiter la donnée de l'un à l'autre. Confondre les deux = le bug n°1 du débutant.

[F:ABV][M:MSK]
C'est quoiUn enregistrement baseUn masque écran
Rempli parRead / ForLa saisie utilisateur
Visible ?Non (mémoire)Oui (à l'écran)
Persiste ?Vers la base via Write/RewriteNon — rien tant qu'on ne sauve pas
Image mentale : [F:] = le tiroir du classeur (le dossier rangé). [M:] = la feuille posée sur le bureau, devant l'utilisateur. Le tiroir ne change que si on y repose la feuille (Write). La feuille n'affiche le dossier que si on l'en sort (Read).

Le transfert — les deux sens

Une seule syntaxe, un signe = tout le record d'un coup. Le sens dépend de quel côté est à gauche :

# base -> écran   (afficher une fiche lue)
[M:YNV0] = [F:YNV]

# écran -> base   (préparer une écriture)
[F:YNV] = [M:YNV0]

C'est exactement ce que fait YNAVETTE à l'ouverture ($LIENS) :

$LIENS
  [M:YNV0]=[F:YNV]        # le record lu remplit l'en-tête écran
  Affzo [M:YNV0]          # ...et on rafraîchit l'affichage
  Grizo [M:YNV0]NAVETTE   # le n° navette : visible mais non saisissable
Return

Puis à la création ($INICRE), le sens s'inverse — on prépare le record avant écriture :

$INICRE
 [F:YNV]=[M:YNV0]         # ce que l'user a saisi -> le record
 [F:YNV]VALFLG=1          # statut "en cours"
Return
Écrire dans [F:] ne change rien à l'écran (l'user ne voit pas). Écrire dans [M:] ne change rien en base (rien n'est sauvé). Symptôme classique : « j'ai mis la valeur mais elle ne s'affiche pas » → tu as écrit côté [F:] au lieu de [M:] (ou oublié Affzo).

Pourquoi 0 et 1 dans YNV0 / YNV1 ?

Un écran a souvent plusieurs blocs. Dans YNAVETTE : [M:YNV0] = le bloc en-tête (n° navette, date, statut), [M:YNV1] = la grille des lignes (palettes). Deux masques, deux buffers. La grille s'indexe ligne par ligne — on verra ça leçon 4.
