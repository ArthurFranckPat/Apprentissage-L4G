Le routeur d'actions

Comment un clic utilisateur devient du code.

Un objet X3 (comme YNAVETTE) n'a pas de main(). Le superviseur Sage pilote l'écran ; à chaque moment-clé — ouverture, clic bouton, sortie d'un champ — il déclenche une action nommée et appelle ton code à un seul point d'entrée : $ACTION.

Le squelette universel

Quasi tous les objets spécifiques commencent ainsi :

$ACTION
  Case ACTION
    When "LIENS"    : Gosub LIENS
    When "PICKE"    : Gosub PICKE
    When "SETBOUT"  : Gosub SETBOUT
    When "EXEBOUT"  : Gosub EXEBOUT
  Endcase
Return

Trois choses à voir :

  • ACTION est une variable que le superviseur remplit avec le nom de l'évènement (tu ne l'assignes jamais).
  • Case … When "X" : Gosub X = un aiguillage. Gosub X saute à l'étiquette $X plus bas, exécute, et revient au Return suivant.
  • Le : n'est pas une fin de ligne — c'est un séparateur d'instructions, qui permet d'écrire When "X" : Gosub X sur une ligne.
Lis le Case comme un menu des gestes métier possibles sur cet écran. Dans YNAVETTE : PICKE = « je clique une palette pour l'ajouter », EXEBOUT = « j'ai cliqué un bouton », LIENS = « l'écran s'ouvre ». Le routeur est la table des matières de l'objet.

Le vocabulaire d'un dev qui débarque

Tu connais déjà le concept (un dispatcher / event loop). Ce qui change en X3, ce sont les noms d'actions standardisés — ils reviennent partout :

ActionDéclenchée quand…
LIENSL'écran charge une fiche (record → masque)
SETBOUTLe superviseur décide quels boutons afficher
EXEBOUTOn clique un bouton (le code est dans BOUT)
